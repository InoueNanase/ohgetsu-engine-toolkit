# 06 · 汉化流水线与工程经验

以《Silvery White ～君と出逢った理由～》为例（34,702 条对话，约 190 万字符）。
不含任何剧本内容，只讲流程与踩过的坑。

## 1. 流水线总览

```
① 解包        PAC -> LZS -> 脚本        （tools/lzss.py + 外部 unpakcer）
② 解析        指令流 -> 文本条目 JSON    （tools/script_tool.py parse）
③ 翻译        JSONL -> 译文 JSONL        （AI + 人工校对，见 §3）
④ 分配码位    用字统计 -> charmap.json   （tools/make_charmap.py）
⑤ 自绘字形    charmap -> 字形位图        （tools/glyph_render.py）
⑥ 生成字库    字形 -> font.bin           （winmm hook 或 tools/font_tool.py）
⑦ 回写脚本    译文定长写回 -> 重打包      （tools/script_tool.py apply）
⑧ 打补丁      EXE：标题 + 全屏修复        （tools/patch_exe.py）
⑨ 部署验证    覆盖文件 + 自动化截图
```

顺序有依赖：④⑤⑥ 必须在 ⑦ 之前完成，否则译文里的字没有字形可显示。

## 2. 文本提取的两个坑

**坑 1：文本没有长度字段。**
只能读到"第一个非法字节"。如果原文里混入了半角标点或特殊符号（引擎允许的），
按 SJIS 规则解析可能提前截断 —— 所以抽取后要**按条数对拍**：
同一脚本的条目数、总字符数，与游戏内实际显示的行数应能对上。

**坑 2：文本不止一种指令承载。**
本引擎对话文本走 `0xAA`，但**角色名、选项、菜单**走别的指令。
只处理 `0xAA` 会导致"对话是中文、人名还是日文"的割裂感。
本项目最终选择保留人名日文（并把这些人名用字加进字库保护集），
换取 100% 的对话覆盖率 —— 这是个取舍，不是技术限制。

## 3. 翻译环节（AI 辅助 + 人工校对）

实际使用的组合：

| 环节 | 工具 | 说明 |
|---|---|---|
| 初翻 | DeepSeek V4.1-Flash / GLM 5.3 | 按场景分批，附带上下文与术语表 |
| 本地润色 | Sakura 本地模型 | 离线批量，统一语气、修机器味 |
| 校对 | 人工 | 抽检 + 全量过一遍人名/术语 |

工程要点：

- **术语表先行**：人名、地名、专有名词先定死，逐条注入 prompt，避免同一角色三种译名。
- **上下文窗口**：按场景（scene）而不是按行送翻，否则代词和语气全乱。
- **长度约束**：给模型的 prompt 里明确"译文不得超过原文 N 个字符"，
  比事后截断有效得多（定长回写的硬限制）。
- **繁简统一**：初翻常混入繁体，需要统一转简，但要**保护例外字**
  （`著 瞭 祇 祐` 等在特定词里必须保留），并修正个别错转换（如 `徬 -> 彷`）。
- **可回滚**：译文用 JSONL 增量保存，每条带 `(文件, 偏移)` 主键，
  重跑只补缺失项，已翻的不动。

## 4. 定长回写的现实问题

约 9% 的译文比原文长。处理手段（按优先级）：

1. **吃尾部空指令**：文本后面的 `00 00` 或空 `AB` 指令可以吃掉，换取几个字节；
2. **排版压缩**：把长句拆成两句、删冗余语气词（要人工确认不损语义）；
3. **保留原文**：极端情况宁可留一句日文，也不要写坏脚本。

绝不要做的是：**盲目截断** —— 半句话比日文更糟。

## 5. 字库验收（必须做）

生成 `font.bin` 后，不要直接进游戏看，先做**平铺预览**：

```bash
python tools/font_tool.py sheet font.bin --start 34000 --count 200 preview.png
```

肉眼过一遍：

- 有没有空白格（字形渲染失败，通常是字体缺字）；
- 有没有明显偏移（垂直对齐错位）；
- 有没有笔画被裁（窗口取小了）。

再进游戏抽查三类字：**常用字**、**繁体深字**（如 鬱 龘）、**标点**（，。「」）。

## 6. 验证与回归

自动化比肉眼可靠，本项目用的手段：

| 目标 | 方法 |
|---|---|
| 启动正常 | `EnumWindows` 找主窗口 + `GetWindowTextA` 读标题 |
| 全屏往返 | 点击菜单 → `GetWindowRect` + `GetSystemMetrics` 对拍 |
| 文本渲染 | 截图 → 人工/视觉模型检查有无乱码、缺字、溢出 |
| 脚本完整性 | 回写后重新 parse，条目数与索引必须与原文一致 |

## 7. 时间分配（真实比例）

- 格式逆向与工具：30%
- 翻译与校对：40%
- 字体（渲染调参、注入、验收）：20%
- 打补丁与验证（全屏/标题/回归）：10%

**字体的 20% 里有一半花在"看起来正常"这件事上** —— 字形渲染出来不难，
难的是 24px 下既清晰又不糊、既统一又不裁边。
